# ES-Plus 三端文档站点重构设计方案

> 版本：2026-08 细化版（基于三站实测现状 + 源码能力审查）

## 结论先行

| 问题 | 结论 |
|---|---|
| 三站是否需要重构？ | 需要一次**统一化重构**——不是推倒重来，而是从"三个各自为政的站"收敛为"一个品牌 + 一套设计语言 + 三种渲染器变体"。 |
| es-plus 能否满足 AI 时代 CRUD 标准化未来？ | **技术上有资格，生态上未就绪**。"配置驱动 + JSON Schema + 三端通用 + AI 工具链"是标准化的正确底座，但从"技术就绪"到"成为标准"之间隔着"用户采纳、生态、第三方集成"三座山。 |

核心洞察：es-plus 最锋利的三把刀——**① 零事件代码联动 ② 一份 Schema 三端通用 ③ AI 原生生成**——在三个站点里没有任何一个被当成"头号案例"重点展示。案例是平铺的组件 API 罗列，不是"痛点 → 解法"的故事。

## 一、现状诊断（基于三站实测）

三站的本质问题：不是"缺内容"，是"缺统一的灵魂"。三站案例总量 96 / 86 / 98，全部按"组件"平铺、每类以 `Basic.vue` 开头。

### 1.1 品牌叙事：口号对齐了，故事没对齐

| 站点 | 首页主口号（实测现状） | 问题 |
|---|---|---|
| es-plus-docs | `中后台 CRUD 的配置层` / `一份配置·三个渲染器·生成即编译` | ✅ 标准 |
| es-eui | `中后台 CRUD 的配置层 · Vue 2 + Element UI` | ✅ 口号对齐，但**无 AI 落地页**（仅顶部 banner 一句） |
| es-pc | `ES-Plus · Ant Design Vue`（H1） | ❌ **标题退化成"技术栈名"**，丢失统一定位口号 |

根因：es-pc 首页 H1 是 `ES-Plus · Ant Design Vue`（`es-pc/src/views/Home.vue:4`），而非统一定位；es-eui 完全没有 AI 页。三站在"AI 原生"这条最重要叙事上强度依次递减（满 / 无 / 有页面但弱）。

### 1.2 案例体系：全是"组件 API 平铺"

- 三站都按 `form/table/dialog/vxe/advanced` 分目录，每类 `Basic.vue` → 进阶。
- **无"痛点→解法"叙事**：只展示"组件能做什么"，不回答"原生要写多少行、es-plus 省了多少"。
- **无 L1–L5 学习梯度**：新访客面对近百案例不知从哪看起；无任何"30 秒上手"聚合入口。
- **最致命**：es-plus 独家的"一份配置三端通用"——三站里没有任何一个案例用三端并排证明它。主站 Home 的"三端通用"区目前只是**三张静态包名卡片**，不是可交互对比。

### 1.3 站点结构：三站不同构

| | 导航形态 | AI 页 | i18n |
|---|---|---|---|
| es-plus-docs | 7 组侧边栏 | AiCrud 活 demo + AiLiveDemo + MCP/CLI 文档 | ✅ zh/en |
| es-eui | 顶部导航 + 子页 | ❌ 无 | ❌ |
| es-pc | 5 项 AntDV 菜单 | AiTools 页（指向主站） | ❌ |

用户跨站切换时，导航逻辑、案例编号、AI 内容深度全变——体验割裂。

## 二、品牌宣传理念设计

### 2.1 品牌叙事演进（三段式）

```
不是"又一个中后台组件库"（打不过 Avue 社区生态）
       ↓
"中后台 CRUD 的配置层"（当前定位：正确但偏静态）
       ↓
"中后台 CRUD 的标准化基础设施 —— AI 时代的默认写法"（目标定位）
```

对标的不是"用哪个 UI 库"，而是"**怎么写 CRUD 这件事本身**"。三站统一收敛到**一句锚点定位 + 三个可验证承诺**：

| 承诺 | 对应优势 | 案例里怎么证明 |
|---|---|---|
| **一份配置** | 30 行 vs 250 行 | 并排 diff 对比 |
| **三端通用** | 单 Schema → Vue2/Vue3/AntDV | 三端切换同一份配置 |
| **AI 原生生成** | MCP + 确定性编译 + CI 可编译保证 | AiCrud 活 demo |

### 2.2 品牌格言（分层，避免俗气）

- **英文 slogan（视觉主标）**：`Write once, render everywhere.`
- **中文定位（H1 统一）**：`中后台 CRUD 的配置层`
- **中文副标（一行讲清机制）**：`一份 JSON 配置 · 三个渲染器 · 生成即编译`

> es-pc 的 H1 必须从 `ES-Plus · Ant Design Vue` 改回统一定位，把 "Ant Design Vue" 降级为副标里的渲染器标注（`本站渲染器：Ant Design Vue`）。

### 2.3 UI 主题风格设计（一套 token，三种渲染器）

三站共享**同一套 design tokens**（品牌色/字体/间距/圆角/阴影），仅底层 UI 库不同，切站视觉一致。

| Token | 建议值 | 理由 |
|---|---|---|
| 品牌主色 | `#2f6bff`（Element 蓝 #409EFF 与 AntDV 蓝 #1677ff 之间的自有科技蓝） | 不偏袒任一渲染器 |
| 强调色 | `#13c2c2` 青绿 | 专用于高亮"配置驱动/数据"概念 |
| 字体/间距/圆角 | 统一，与 UI 库解耦 | 已有 `docs/tokens/design-tokens.css` + `sync-tokens.mjs` 分发基建 |

此项已有基建（`design-tokens.css` + CI drift guard），只需三站都消费它。

### 2.4 站点结构统一（三站同构骨架）

```
首页（品牌故事 + 30秒上手 + 三个承诺）
├── 快速开始（安装 / 注册 / 第一个 CRUD）
├── 核心案例（L1–L5 场景化梯度，见第三节）
├── 组件 API（EsForm / EsTable / EsDialog / EsCrudPage / useDialog）
├── 引擎（vxe / virtual）—— 三站都应有
├── AI 工具链（MCP / CLI / AiCrud）—— 三站都应有
└── 生态（迁移指南 / 竞品对比 / FAQ）
```

**关键补齐**：es-eui 从"无 AI"补齐为**指向主站的统一 AI 叙事页**（MCP 本就能生成 vue2 target，跨渲染器）；es-pc 的 AiTools 保留。三站 AI 页共享同一段文案。

## 三、功能案例体系设计（核心）

### 3.1 设计原则

> 每个案例不是"展示一个组件"，而是"**解决一个真实 CRUD 痛点**"，并回答"原生怎么写 vs es-plus 怎么写"。

三个硬性要素：**① 痛点前置 ② 量化对比（原生 N 行 vs es-plus M 行 并排 diff）③ 三端通用元叙事贯穿**。

### 3.2 五级案例梯度

**L1 — 30 秒上手（消除陌生感）** · 目标：30 秒内让访客"看懂了、想试了"

| 案例 | 痛点 | 优势 |
|---|---|---|
| ① 配置化表单 | 8 字段查询表单要写 70 行模板 | 一行配置一个字段 |
| ② 配置化表格 | 列+操作列+分页要写 60 行 | 列配置 + btns 操作列 |
| ③ 编程式弹窗 | 模板声明弹窗要 45 行 | `useDialog()` 函数调用 |

落地：三站各建一个 `L1-QuickStart` 聚合页，把这 3 个案例放最前，配"读完预计 30 秒"标记。

**L2 — 全链路联动（头号案例，放 C 位）**

> **④「零事件代码的 CRUD」**——全站最重要案例。痛点：原生"查询→重置→翻页"要 4 个事件函数还易踩"拿最新表单值"坑。解法：EsForm 嵌套 EsTable + `triggerEvent:true`，**0 行事件代码**。展示：并排「原生 250 行 ↔ es-plus 30 行」diff。

**L3 — 复杂 CRUD 痛点（覆盖横切关切）**

| 案例 | 痛点 | 优势 |
|---|---|---|
| ⑤ 跨页选择 | 批量审核跨 3 页，原生切页就丢 | `cachePageSelection` 一行 |
| ⑥ 远程下拉+条件显隐 | 分类接口拉取 + 字段联动 | `apiParams` + `isHidden` |
| ⑦ 任意后端适配 | 5 个 BFF 协议各不同 | `configTableOut` 递归映射 |
| ⑧ 按钮权限+i18n | 权限点改名要全工程替换 | `permission` 声明式 |

**L4 — 复杂场景适配（vxe/virtual，突破"组件库能力上限"）**

| 案例 | 痛点 | 优势 |
|---|---|---|
| ⑨ 万行数据 | el-table 卡顿 | `virtual:true` 虚拟滚动 |
| ⑩ 行内编辑/行编辑校验 | 表格内直接改+校验 | vxe `editConfig` |
| ⑪ 树形/多级表头/合并单元格 | 层级+组头+复杂报表 | `engine:'vxe'` |
| ⑫ CRUD+弹窗综合 | 增删改查全闭环 | EsCrudPage / useDialog |

> es-pc 侧此层已补齐到 17 个 vxe 案例（本轮完成），是三站中 L4 最完整的，可作其他两站对齐参照。

**L5 — 个性化适配+扩展（render 逃生舱，证明"不被 DSL 锁死"）**

| 案例 | 痛点 | 优势 |
|---|---|---|
| ⑬ 自定义单元格 | 进度条/富文本/图片 | `render` 逃生舱 |
| ⑭ 第三方控件接入 | 需要 UI 库没有的控件 | `render` 自定义组件 |
| ⑮ 全局配置+按需导入+主题 | 团队统一默认值 | `app.use(ESPlus,{...})` + Resolver + `vxeConfig`/`vxeOn` 原生透传 |

### 3.3 贯穿全站的"三端通用"元叙事（最高优先级）

- 每个核心案例顶部放**三端切换器**（Vue3 / Vue2 / AntDV），展示同一份 Schema 在三端渲染出一致界面。
- 收口一句：`换一行 import，你的 Vue 2 项目就拥有了 Vue 3 的未来。`
- **技术约束（见第六节）**：三端 UI 库（Element Plus / Element UI-Vue2 / AntDV）无法在同一个 Vue3 应用里同时活体渲染，因此"三端切换器"应采用**"同一份 Schema 源码 + 三端截图/构建产物快照"**方案，而非单页三活体实例。

### 3.4 AI 时代案例（前瞻区）

| 案例 | 形式 | 现状 |
|---|---|---|
| ⑯ AI 一句话生成 CRUD | AiCrud 活 demo | 主站已有，es-eui/es-pc 缺 → 补指向主站 |
| ⑰ MCP 集成 | Claude Code 里协议流可视化 | 主站 AiCrud 有 Trace tab，可复用 |

## 四、统一化 / 标准化 / 个性化

| 维度 | 设计 |
|---|---|
| **统一化** | 一个品牌、一套 design token、一套同构站点结构、一套 L1-L5 案例叙事——三站只是"渲染器变体" |
| **标准化** | 把"配置 Schema"作为标准宣传：JSON Schema 公开 + zod 校验 + CI 可编译保证——"CRUD 标准化"的载体 |
| **个性化** | render 逃生舱 + 全局配置 + Resolver 按需导入 + `vxeConfig`/`vxeOn` 原生透传，证明"标准但不僵化" |

## 五、技术实施方案（详细、可行、分阶段）

### 5.0 总原则

- **不推倒重来**：三站现有 260+ 案例保留，重构的是"组织方式 + 叙事外壳 + 品牌层"，不是重写案例。
- **共享层单一真源**：品牌 token、slogan 文案、L1-L5 案例清单、三端元叙事组件，都从 `docs/` 单一真源分发，用 CI drift guard 防漂移（复用现有 `sync-tokens.mjs` / `sync-docs.mjs` 模式）。
- **分站落地**：每阶段先在主站 es-plus-docs 落地验证，再同步到 es-pc / es-eui。

### 5.1 阶段一：品牌层统一（P0，成本低见效快）

| 动作 | 文件 | 做法 |
|---|---|---|
| es-pc H1 定位修正 | `es-pc/src/views/Home.vue:4-9` | H1 改 `中后台 CRUD 的配置层`，副标 `一份 JSON 配置 · 三个渲染器 · 生成即编译`，`Ant Design Vue` 降为 `本站渲染器：Ant Design Vue` 徽章 |
| 三站 hero 三承诺对齐 | 三站 Home hero 区 | 统一 3 张承诺卡：一份配置 / 三端通用 / AI 原生生成 |
| slogan 文案单一真源 | 新增 `docs/brand/slogan.json` + `sync-docs.mjs` 扩展 | 三站从同一 JSON 读 slogan/承诺文案，CI `--check` 防漂移 |
| design token 全量消费 | 三站样式入口 | es-pc 已引 `design-tokens.css`；es-plus-docs / es-eui 补引入并替换硬编码色值为 `var(--es-brand-primary)` 等 |

### 5.2 阶段二：站点结构同构（P2）

- 定义**同构导航骨架**（首页 / 快速开始 / 核心案例 L1-L5 / 组件 API / 引擎 / AI 工具链 / 生态）。
- es-plus-docs：7 组 → 收敛映射到骨架（起步→快速开始，组件/高级→组件API+核心案例，AI 编码→AI 工具链）。
- es-pc：`DocLayout.vue` 菜单从 5 项扩展为骨架分组（已有 组件组/高级组/AI 工具链，补"核心案例"组）。
- es-eui：顶部导航 → 侧边栏骨架对齐；补 AI 工具链页。
- **交付物**：一份 `docs/site-structure.md` 定义骨架，三站各自映射。

### 5.3 阶段三：L1/L2 头号案例（P0-P1）

- **L1 QuickStart 聚合页**：三站各建 `views/QuickStart.*`，聚合已有的 form-basic / table-basic / dialog-basic 三案例 + "30 秒"标记。**复用现有案例，不新写**。
- **L2 零事件 CRUD 案例**：三站已有类似案例（es-pc `AdminPage.vue`、主站 advanced 联动案例），**提炼为头号案例** + 补"原生 N 行 vs es-plus M 行"并排 diff 组件。
- **并排 diff 组件**：新增共享组件 `CodeDiff`（左原生右 es-plus，行数徽章）。三站各实现一份（技术栈不同），接口一致。

### 5.4 阶段四：三端元叙事组件（P1，需先解决技术约束）

- **约束**：单页无法三端活体渲染（见第六节结论）。
- **方案**：`TriRenderTabs` 组件——Tab 切 Vue3 / Vue2 / AntDV，每 Tab 展示**同一份 Schema 源码**（高亮）+ 该端**渲染快照**（构建期截图，存 `docs/tri-render/*.png`）。
- 快照生成：脚本 `scripts/gen-tri-render-snapshots.mjs`（Playwright 对三站同一案例截图），纳入 CI。
- 铺设范围：L2 头号案例 + L1 三案例 + 每个 L3/L4 代表案例顶部。

### 5.5 阶段五：AI 叙事补齐（P2）

- es-eui 新增 `AiTools` 页，文案与 es-pc `AiTools.vue` 共享（从 `docs/ai/ai-tools.md` 单一真源）。
- 三站首页均保留/补齐"AI 一句话生成 CRUD"入口卡，指向主站 AiCrud。

### 5.6 落地优先级总表

| 优先级 | 动作 | 成本 | 影响 |
|---|---|---|---|
| P0 | es-pc H1 定位修正；三站 hero 三承诺对齐 | 低 | 立刻消除品牌割裂 |
| P0 | L2「零事件 CRUD」头号案例 + 并排 diff | 中 | 首页第一印象 |
| P1 | TriRenderTabs 三端切换器 + 快照脚本 | 中高 | 独家差异化落地 |
| P1 | 三站 L1「30 秒上手」聚合页 | 低 | 降低上手门槛 |
| P2 | es-eui 补 AI 页；三站 AI 文案共享 | 低 | 补齐叙事短板 |
| P2 | design token 全量消费 + 结构同构 | 中 | 视觉一致性 |

## 六、源码能力审查（配合本方案的能力短板/Bug 排查）

### 6.3 三端「活体渲染」技术裁决（影响 §3.3 / §5.4）

- **现状**：主站"三端通用"区是**三张静态卡片**（`Home.vue:172-196`），无 iframe、无截图、无活体渲染；且 es-plus-docs 只装了 Element Plus，未装 antdv/vue2 依赖。
- **可行性**：Element Plus + Ant Design Vue **可**在同一 Vue3 应用共存（都是 Vue3 库）；但 **`@es-plus/vue2` + Element UI 是 Vue2-only，无法挂进 Vue3 应用**（`install(Vue,options)` 签名 + Element UI 皆 Vue2）。
- **裁决**：单页"三端活体切换"**只对 vue3 + antdv 现实可行**，Element UI/Vue2 端必须走 **iframe 独立 bundle 或构建期截图**。
- **落地方案（§5.4 已采纳）**：`TriRenderTabs` = **同一份 Schema 源码 + 三端渲染快照**（Playwright 构建期截图入 `docs/tri-render/*.png`，CI 生成），而非单页三活体实例。这是唯一稳妥且成本可控的方案。

### 6.4 方案可行性结论

- **无阻塞项**：L1–L5 案例梯度依赖的能力全部具备（零事件联动、跨页选择、远程选项+条件显隐、后端适配、按钮权限+i18n、render 逃生舱、全局配置+Resolver）。
- **需先行修复（P0）**：`FormType` 补 `InputNumber`（低成本、影响所有类型安全的表单案例）。
- **需文档规避（P1）**：virtual/patchHtmlRowSpans 的 vue3 专属性、`isHiden` 只在 vue2、`applyConfigTableOut` 死代码——在案例说明里显式标注渲染器差异，不夸大"三端完全一致"。
- **需核实（P1）**：主站 fork 组件与已发布包的分叉，避免"文档演示的不是真库"。
