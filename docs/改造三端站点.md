  一、现状诊断（基于源码 + 站点审计）

  三站的本质问题：不是"缺内容"，是"缺统一的灵魂"。

  ┌──────────┬───────────────────────────────────────────────────┬──────────────────────────────────────────────────┐
  │   维度   │                       现状                        │                       问题                       │
  ├──────────┼───────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ 品牌     │ 曾分裂 ES-Plus/ES Plus/ES-EUI（已修）             │ 修复后仍未形成"一个品牌故事"                     │
  ├──────────┼───────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ 技术栈   │ vue-cli(Vue2) / Vite4 / Vite6 三代并存            │ 维护成本高，三站体验割裂                         │
  ├──────────┼───────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ 叙事     │ 主站讲"AI 原生"，es-eui 无 AI，es-pc 只宣传无落地 │ 三个站讲三个不同的故事                           │
  ├──────────┼───────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ 案例     │ ~96/86/81 个，按"组件"平铺                        │ 没有"从简单到复杂"的学习路径，用户不知道从哪开始 │
  ├──────────┼───────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ 核心优势 │ 三端单 Schema 是独家差异化                        │ 没有一个案例专门演示"同一份配置三端通用"         │
  └──────────┴───────────────────────────────────────────────────┴──────────────────────────────────────────────────┘

  核心洞察：es-plus 最锋利的三把刀——①零事件代码联动 ②一份 Schema 三端通用 ③AI
  原生生成——在三个站点里没有任何一个被当成"头号案例"重点展示。案例是平铺的组件 API 罗列，不是"痛点 → 解法"的故事。

  ---
  二、品牌宣传理念设计

  2.1 一句话定位（收敛所有叙事的锚点）

  ▎ "一份 JSON 配置，三个渲染器通用，AI 原生生成 —— 中后台 CRUD 的标准化答案。"

  拆解为三个可验证的承诺（每个都能在案例里证明）：

  ┌─────────────┬──────────────────────────────────┬────────────────┐
  │    承诺     │             对应优势             │    可验证性    │
  ├─────────────┼──────────────────────────────────┼────────────────┤
  │ 一份配置    │ 配置驱动（30 行 vs 250 行）      │ 并排 diff 对比 │
  ├─────────────┼──────────────────────────────────┼────────────────┤
  │ 三端通用    │ Vue2/Vue3/AntDV 单 Schema        │ 同配置三端截图 │
  ├─────────────┼──────────────────────────────────┼────────────────┤
  │ AI 原生生成 │ MCP + 确定性编译 + CI 可编译保证 │ AiCrud 活 demo │
  └─────────────┴──────────────────────────────────┴────────────────┘

  2.2 品牌叙事演进

  - 不要：定位成"又一个中后台组件库"（打不过 Avue 的社区）。
  - 要：定位成"中后台 CRUD 的标准化基础设施"——对标的是"怎么写 CRUD"这件事本身，而不是"用哪个组件库"。

  2.3 品牌格言

  - 英文 slogan："Write once, render everywhere."（一份配置，处处渲染）
  - 中文副标："配置即页面，AI 即协作。"

  ---
  三、UI 主题风格设计

  3.1 统一设计语言（Design Tokens）

  三站共享同一套设计 token（品牌色、字体、间距、圆角、阴影），只有底层 UI 组件不同（Element Plus / Element UI /
  AntDV）。这样用户切到任一渲染器文档，视觉和结构体验一致。

  ┌───────────┬─────────────────────────────────────────────────────────────────────────────────────────┐
  │   Token   │                                          建议                                           │
  ├───────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 品牌主色  │ 一个能同时贴合 Element 蓝和 AntDV 蓝的中性科技蓝（如 #409EFF→#1677ff 之间取一个自有蓝） │
  ├───────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 强调色    │ 用于"配置驱动"高亮的独有色（如青绿 #13c2c2，呼应"数据/配置"）                           │
  ├───────────┼─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 字体/间距 │ 统一，与三端 UI 库解耦                                                                  │
  └───────────┴─────────────────────────────────────────────────────────────────────────────────────────┘

  3.2 站点结构统一（三站同构）

  首页（品牌故事 + 30秒上手 + 三个承诺）
  ├── 快速开始（安装/注册/第一个 CRUD）
  ├── 核心案例（L1-L5 场景化，见下）
  ├── 组件 API（EsForm/EsTable/EsDialog/EsCrudPage/useDialog）
  ├── 引擎（vxe / virtual，三站都应有）
  ├── AI（MCP/CLI/AiCrud，三站都应有）
  └── 生态（迁移指南/竞品对比/FAQ）

  关键：es-eui（Vue2）和 es-pc（AntDV）的 AI/MCP/CLI 内容，应从"缺失"补齐为"指向主站的统一 AI 叙事"——因为 AI 工具链本身是跨渲染器的（MCP 能生成
  vue2/vue3/antdv 三种 target）。

  四、功能案例体系设计（核心重点）

  4.1 设计原则

  ▎ 每个案例不是"展示一个组件"，而是"解决一个真实 CRUD 痛点"，并回答"原生怎么写，es-plus 怎么写"。

  三个硬性要素：
  1. 痛点前置：先说"这个需求在原生的成本"，再给 es-plus 的解法。
  2. 量化对比：每个案例配"原生 N 行 vs es-plus M 行"的并排 diff。
  3. 元叙事贯穿：每个案例都标注"本配置在 Vue2/Vue3/AntDV 三端通用"，用三端 Tab 切换展示同一份配置的三种渲染。

  4.2 五级案例梯度（从简单到复杂）

  L1 — 30 秒上手（单个组件，消除陌生感）

  ┌──────────────┬──────────────────────────────┬──────────────────────┐
  │     案例     │             痛点             │       突出优势       │
  ├──────────────┼──────────────────────────────┼──────────────────────┤
  │ ① 配置化表单 │ 8 字段查询表单要写 70 行模板 │ 一行配置一个字段     │
  ├──────────────┼──────────────────────────────┼──────────────────────┤
  │ ② 配置化表格 │ 列 + 操作列 + 分页要写 60 行 │ 列配置 + btns 操作列 │
  ├──────────────┼──────────────────────────────┼──────────────────────┤
  │ ③ 编程式弹窗 │ 模板声明弹窗要 45 行         │ useDialog() 函数调用 │
  └──────────────┴──────────────────────────────┴──────────────────────┘

  目标：30 秒内让访客"看懂了、想试了"。

  L2 — 全链路联动（头号案例，es-plus 的灵魂）

  ▎ 案例④「零事件代码的 CRUD」 —— 这是全站最重要的案例，必须放在核心 C 位。

  痛点：原生写"查询→重置→翻页"要 4 个事件处理函数，还容易踩"拿最新表单值"的坑。

  解法：EsForm 嵌套 EsTable，triggerEvent: true，查询/重置/分页全自动联动，0 行事件代码。

  展示形式：并排「原生 250 行 ↔ es-plus 30 行」的 diff 动画，是首页和案例页的第一印象。

  L3 — 复杂 CRUD 痛点（进阶，覆盖横切关切）

  ┌───────────────────────┬─────────────────────────────────────────┬───────────────────────────────┐
  │         案例          │                  痛点                   │             优势              │
  ├───────────────────────┼─────────────────────────────────────────┼───────────────────────────────┤
  │ ⑤ 跨页选择            │ 批量审核 50 条分布在 3 页，原生切页就丢 │ cachePageSelection: true 一行 │
  ├───────────────────────┼─────────────────────────────────────────┼───────────────────────────────┤
  │ ⑥ 远程下拉 + 条件显隐 │ 分类从接口拉 + 字段联动显隐             │ apiParams + isHidden          │
  ├───────────────────────┼─────────────────────────────────────────┼───────────────────────────────┤
  │ ⑦ 任意后端适配        │ 5 个 BFF 协议各不同                     │ configTableOut 递归映射       │
  ├───────────────────────┼─────────────────────────────────────────┼───────────────────────────────┤
  │ ⑧ 按钮权限 + i18n     │ 权限点改名要全工程替换                  │ permissionValue 声明式        │
  └───────────────────────┴─────────────────────────────────────────┴───────────────────────────────┘

  L4 — 复杂场景适配（vxe/virtual 引擎，突破"组件库能力上限"）

  ┌─────────────────┬──────────────────────┬────────────────────────┐
  │      案例       │         痛点         │          优势          │
  ├─────────────────┼──────────────────────┼────────────────────────┤
  │ ⑨ 万行数据      │ 原生 el-table 卡顿   │ 虚拟滚动 virtual: true │
  ├─────────────────┼──────────────────────┼────────────────────────┤
  │ ⑩ 行内编辑      │ 表格内直接改数据     │ vxe editConfig         │
  ├─────────────────┼──────────────────────┼────────────────────────┤
  │ ⑪ 树形/多级表头 │ 层级数据 + 组头      │ vxe engine: 'vxe'      │
  ├─────────────────┼──────────────────────┼────────────────────────┤
  │ ⑫ 多弹窗编排    │ 新增/编辑/查看多弹窗 │ EsCrudPage 一份 Schema │
  └─────────────────┴──────────────────────┴────────────────────────┘

  L5 — 个性化适配 + 扩展（render 逃生舱，证明"不被 DSL 锁死"）

  ┌──────────────────────────────┬─────────────────────────┬───────────────────────────────────┐
  │             案例             │          痛点           │               优势                │
  ├──────────────────────────────┼─────────────────────────┼───────────────────────────────────┤
  │ ⑬ 自定义单元格               │ 进度条/富文本/图片预览  │ render 逃生舱                     │
  ├──────────────────────────────┼─────────────────────────┼───────────────────────────────────┤
  │ ⑭ 第三方控件接入             │ 需要 Element 没有的控件 │ render 自定义组件                 │
  ├──────────────────────────────┼─────────────────────────┼───────────────────────────────────┤
  │ ⑮ 全局配置 + 按需导入 + 主题 │ 团队统一默认值          │ app.use(ESPlus, {...}) + Resolver │
  └──────────────────────────────┴─────────────────────────┴───────────────────────────────────┘

  4.3 贯穿全站的"三端通用"元叙事

  这是 es-plus 独一无二、竞品无法复制的差异化，必须作为最高优先级的视觉元素：

  - 每个案例顶部放一个 三端 Tab 切换器（Vue3 / Vue2 / AntDV），展示同一份配置在三端渲染出相同的界面。
  - 一句话收口："换一行 import，你的 Vue 2 项目就拥有了 Vue 3 的未来。"
